# Data Model: Tweet to Quote Conversion System

**Feature**: 002-tweet-to-quote-conversion
**Date**: 2025-10-24
**Status**: Design Complete

## Overview

This document defines the data structures for the three-stage tweet-to-quote conversion pipeline: source Twitter data, intermediate staging format, and final quote records.

---

## Entity Definitions

### 1. Source Tweet Record (Input)

**Source**: `etc/tweets.js` - Twitter archive export format

**Structure**: JSON wrapped in JavaScript assignment (`window.YTD.tweets.part0 = [...]`)

**Fields** (relevant subset of Twitter archive format):

```typescript
interface SourceTweet {
  tweet: {
    id_str: string;                    // Unique tweet identifier
    full_text: string;                 // Complete tweet text
    created_at: string;                // RFC 2822 timestamp
    favorite_count: string;            // Likes count (string in archive)
    retweet_count: string;             // Retweets count (string in archive)

    // Media references (optional)
    entities?: {
      media?: Array<{
        media_url_https: string;       // Image/video URL
        type: string;                  // "photo" | "video" | "animated_gif"
      }>;
    };

    // Extended media for multi-image tweets (optional)
    extended_entities?: {
      media?: Array<{
        media_url_https: string;
        type: string;
      }>;
    };
  };
}
```

**Validation Rules**:
- `full_text` must exist and be non-empty (tweets without text are excluded)
- Retweets identified by `full_text` starting with "RT @"
- Tweets with only URLs and no other text are excluded

**State Transitions**: N/A (immutable source data)

---

### 2. Staging Entry (Intermediate)

**Source**: Generated by `extract_tweets.py` → `etc/staging/tweets_staging.json`

**Purpose**: Human-reviewable format allowing manual edits before final conversion

**Structure**: JSON array with metadata

```typescript
interface StagingFile {
  metadata: {
    extracted_at: string;              // ISO 8601 timestamp
    source_file: string;               // Path to source (e.g., "etc/tweets.js")
    total_extracted: number;           // Count of entries
    version: string;                   // Schema version (e.g., "1.0")
  };

  tweets: StagingEntry[];
}

interface StagingEntry {
  tweet_id: string;                    // From source id_str
  text: string;                        // From source full_text (exact copy)
  created_at: string;                  // Preserved as-is from source (RFC 2822 format)
  is_retweet: boolean;                 // true if text starts with "RT @"
  favorite_count: number;              // Converted to number from string
  retweet_count: number;               // Converted to number from string
  media_urls: string[];                // All media_url_https from entities and extended_entities

  // Human-editable fields
  notes?: string;                      // Optional curator notes (not used in final conversion)
  exclude?: boolean;                   // If true, skip this entry during conversion
}
```

**Validation Rules**:
- `tweet_id` must be unique within staging file
- `text` must be non-empty (enforced during extraction)
- `is_retweet` automatically set based on text prefix "RT @"
- Entries with `is_retweet: true` are automatically excluded from final conversion
- Entries with `exclude: true` are manually excluded by curator

**State Transitions**:
1. **Extracted**: Entry created from source tweet
2. **Reviewed**: Curator may edit text, add notes, or mark for exclusion
3. **Ready**: Entry will be included in conversion (not a retweet and not marked exclude)

---

### 3. Quote Record (Output)

**Source**: Generated by `convert_to_quotes.py` → `app/data/quotes.json`

**Purpose**: Application-ready quote data matching API schema

**Structure**: JSON array (appended to existing file)

```typescript
interface QuoteFile {
  quotes: QuoteRecord[];
}

interface QuoteRecord {
  id: string;                          // Format: "quote-XXX" where XXX is incrementing number
  quote: string;                       // From staging entry text (exact copy)
  primarySpeaker: string | null;       // Empty/null (filled by separate curation process)
  imageUrl?: string | null;            // First media URL from staging entry, or null
}
```

**Validation Rules**:
- `id` must be unique across all quotes in the file
- `id` format must match regex: `^quote-\d+$` (e.g., "quote-1", "quote-42", "quote-999", no zero-padding)
- `quote` must be non-empty
- `primarySpeaker` extracted from text if it matches "Name:" prefix pattern (alphabetical characters and spaces followed by colon), otherwise set to empty string `""` or `null`
- `imageUrl` is optional; if tweet has media, use first URL, otherwise omit or set to null

**Identity & Uniqueness**:
- Primary key: `id` field
- Uniqueness enforced by ID generation algorithm:
  1. Scan existing quotes to find highest numeric ID
  2. Start new IDs from max + 1
  3. If collision detected, auto-increment to next available

**State Transitions**: N/A (final immutable output)

---

### 4. Media Asset (Download Artifact)

**Source**: Downloaded by `download_media.py` → `media/tweet_images/`

**Purpose**: Local copies of tweet media for potential S3 upload

**Structure**: Individual image/video files

```typescript
interface MediaAsset {
  // File naming convention
  filename: string;                    // Format: "<tweet_id>_<index>.<extension>"

  // Metadata (tracked in download log, not stored with file)
  source_url: string;                  // Original media_url_https
  tweet_id: string;                    // Associated tweet
  downloaded_at: string;               // ISO 8601 timestamp
  file_size_bytes: number;             // Size for skip-if-exists check
  status: "success" | "error" | "skipped";
}
```

**Validation Rules**:
- Filename must not contain path separators
- Extension derived from URL or Content-Type header
- Skip download if file exists with matching size

**Relationships**:
- Many-to-one: Multiple media assets may reference the same tweet_id
- One-to-one: Each media asset corresponds to one source URL

│ etc/tweets.js   │ (Source: Twitter archive)

         │ • Remove unwanted entries
         │ • Edit quote text

│ etc/staging/            │ (Reviewed)

└────────┬────────────────┘

         │ • Filter excluded entries
         │ • Generate quote IDs
         │ • Append to existing
         ▼

└─────────────────────────┘

         ┌────────────────────┐

## Relationships

### Tweet ID Lineage

```text
SourceTweet.tweet.id_str
  → StagingEntry.tweet_id
    → MediaAsset.tweet_id (for filename)

(Note: tweet_id does NOT map to QuoteRecord.id)
```

### Media URL Mapping

```text
SourceTweet.tweet.entities.media[].media_url_https
  → StagingEntry.media_urls[] (all photo URLs preserved)
    → QuoteRecord.imageUrl (first URL only from media_urls[0])
    → MediaAsset.source_url (all URLs downloaded individually)
```

### Text Preservation Path

```text
SourceTweet.tweet.full_text (exact Unicode)
  → StagingEntry.text (exact copy)
    → [Human may edit during review]
    → QuoteRecord.quote (exact copy of reviewed text)
```

## Data Validation Checklist

### Extraction Phase
- [ ] Source file is valid JSON (after stripping JS wrapper)
- [ ] All tweets have `full_text` field
- [ ] Tweet IDs are unique
- [ ] Retweets correctly flagged
- [ ] Media URLs are well-formed HTTPS URLs

### Staging Phase
- [ ] Staging file is valid JSON
- [ ] Metadata fields populated correctly
- [ ] All entries have required fields
- [ ] No duplicate tweet IDs

### Conversion Phase
- [ ] Existing quotes.json loaded successfully
- [ ] Generated quote IDs are unique
- [ ] No IDs collide with existing quotes
- [ ] Text preserved exactly from staging
- [ ] Output is valid JSON

### Media Download Phase
- [ ] All URLs are HTTPS
- [ ] Filenames are safe (no path traversal)
- [ ] Downloaded files match expected size
- [ ] Errors logged for failed downloads

## Storage Estimates

**Staging File Size** (for reference):
- ~500 bytes per staging entry (includes metadata)
- 1,000 tweets ≈ 500KB staging file
- Human-editable in any text editor

**Quote File Growth**:
- ~200 bytes per quote record (minimal fields)
- 1,000 new quotes ≈ 200KB added to quotes.json
- Append-only, no size limits expected (<10MB total anticipated)

**Media Storage**:
- Variable size per image (typically 50KB - 500KB for Twitter images)
- 1,000 tweets with 30% having media, avg 200KB = ~60MB total

---

## Constraints & Assumptions

1. **Single Tweet Archive**: Initial version processes one tweets.js file; no multi-part merge
2. **Single Media Per Quote**: Only first media URL included in imageUrl field
3. **No Schema Migration**: Existing quotes.json assumed to match current schema
4. **UTF-8 Encoding**: All text files use UTF-8 throughout pipeline
5. **Append-Only Quotes**: No update or delete operations on existing quotes
6. **Local Execution**: No distributed processing or database persistence
